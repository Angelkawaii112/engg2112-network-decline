# 我们做了什么、为什么这样做、实际发现什么

研究题目：**新南威尔士州移动网络质量的多指标评估与偏远程度差异研究**。

这次只研究移动网络的下载、上传、延迟和ABS官方偏远程度；没有做固网对比、运营商识别、SEIFA扩展，也没有训练新预测模型。不能把这些没有做的内容写成成果。所有新增文件都位于本实验目录，不改组员的部分。

## 第1步：先确定问题与规则

**做了什么：** 在计算新结果前写下 `PROTOCOL.md`，明确三件事：只看下载会遗漏什么；各偏远类别的样本表现怎样；哪些地区的数据不足以判断。

**为什么：** 不能看完结果后，为得到更好看的数字再改阈值。预先说明主要规则、分母和敏感性检查，可以让研究过程更透明。

**此时得出什么：** 只有研究设计，还没有数据结论。20%是项目定义，不是官方故障标准。

## 第2步：自己从官方来源取得数据

**做了什么：** 从Ookla官方公开存储读取2019Q1至2026Q1的29个季度，并单独下载ABS 2021 Remoteness Areas边界。不导入组员已经过滤过的分析面板。为节约存储，只查询需要的地理范围，再将细网格合并到zoom-12。

**怎么算：** 一块小网格测100次，另一块测10次，合并均值时前者权重更高；这是“按测速次数加权的平均数”，不是中位数。设备数量跨网格相加也不能当成独立人数。

**实际结果：** 初步地理范围得到68,591条网格—季度记录。这个范围包含NSW以外地区，不能直接拿来写NSW结论。每季度的来源网址、查询和数据哈希都保存在 `provenance/`。

## 第3步：用ABS边界判断地区类型

**做了什么：** 把每个网格中心与官方多边形匹配，只接受唯一落在NSW五类偏远地区中的中心。不强行把落在海面或边界外的点分配给最近地区。

**为什么：** 测速少不等于偏远。使用官方地理分类，才能把“地理偏远程度”和“数据采样多少”区分开。

**实际结果：** 保留37,449条NSW记录，涉及4,443个不同网格；27,728条在其他地区，3,414条没有匹配到多边形。NSW内有846个网格跨越不止一种偏远类别，所以额外做了排除混合网格的敏感性检查。

**限制：** 这是网格中心归类，不表示整块网格都属于同一类别；历史年份统一使用2021年分类，也不是还原当时的全部地理变化。

## 第4步：区分“网络恶化”和“无法判断”

**做了什么：** 对基准季度t，检查紧接着的t+1和t+2。三个季度都要有有效的下载、上传、延迟数值，每季度至少50次测速。

例子：下载从100变成80、80，满足规则；从100变成80、90，则不满足。这里是两个后续季度都比同一个基准差20%，不是每季度继续跌20%。延迟越高越差，所以方向相反。

**为什么：** 一次波动不一定持续；缺季度不能拿更晚的数据顶替；缺数据不能标成“正常”。三个指标还必须使用同一组符合条件的记录，才能公平比较。

**实际结果：**

| 状态 | 记录数 | 怎么解释 |
| --- | ---: | --- |
| 符合判断条件 | 3,145 | 可以比较三个指标 |
| 缺后续季度 | 15,115 | 无法验证持续变化 |
| 测速不足 | 16,855 | 至少一个季度不足50次 |
| 指标或源数据无效 | 26 | 不参与判断 |
| 最后两个季度 | 2,308 | 后续窗口未完整，不能算正常 |
| 合计 | 37,449 | 与NSW输入一致 |

每条记录只进入一个状态，优先级见 `DATA_SOURCES.md`。这里没有把所有从未出现过的网格—季度组合补出来，所以不能把这些比例说成全州覆盖率。

## 第5步：比较“只看下载”和“三指标一起看”

**做了什么：** 分别标记下载下降、上传下降、延迟升高，再检查上传或延迟恶化但下载未满足恶化规则的情况。

**实际结果：** 下载规则标记178条；三指标共标记437条；另外259条没有被下载规则涵盖。其中上传单独恶化141条、延迟单独恶化95条、上传与延迟一起恶化23条。

两个比例不能混：

- 259÷437＝**59.27%**：在所有被三指标标记的记录里，下载规则没有涵盖的比例。
- 259÷3,145＝**8.24%**：在所有能够判断的记录里，新增标记记录的比例。

**可以写：** 在本研究的样本和规则下，只看下载会遗漏其他类型的持续恶化。

**不能写：** 发现259次真实网络故障、59%的居民网络不好、模型准确率提高59%。我们没有测这些。

**一个真实例子：** 网格 `311212310133`，基准2019Q3，属于Outer Regional。三个季度的上传均值为23.95、18.64、15.40 Mbps，后两季都比基准低至少20%；下载为36.68、32.01、23.13 Mbps，只有第二个后续季度下降达到20%，所以下载规则不标记、上传规则标记。对应测速次数为130、95、132。这个例子是按网格编号和时间排序选出的首个“上传单独恶化”记录，不是挑最大的跌幅。

## 第6步：比较地区，同时暴露数据盲点

**做了什么：** 按五个ABS类别统计符合条件的数量、比例和恶化率。还比较同一批季度，避免某组主要出现在早期、另一组主要出现在晚期造成误导。

**实际结果：** 大城市有1,829条可判断记录，Inner Regional有1,210条，Outer Regional有104条，Remote仅2条且来自同一个网格，Very Remote为0条。各组在“已观测且窗口成熟”的记录中，可判断比例分别为77.37%、6.87%、0.80%、0.11%、0%。

大城市与Inner Regional有27个共同季度。将每个季度等权平均，新增上传／延迟恶化率分别为7.27%和10.09%。这是样本中的描述性差异，不足以证明偏远程度造成网络变差。

**最重要的限制：** 五类地区没有共同满足条件的季度，不能硬做五类排名。Remote的50%其实只是2条里有1条，不能拿来下强结论；图中不把这类极小样本画成可排名的柱状值，CSV保留原始数字。

## 第7步：换规则，看结论是不是容易翻转

**做了什么：** 保留主规则，并完整报告六个预先设计的变体。

| 规则 | 新增上传／延迟记录 ÷ 全部被标记记录 |
| --- | ---: |
| 主规则：20%、每季至少50次测速 | 259/437＝59.27% |
| 改成15% | 379/660＝57.42% |
| 改成25% | 194/306＝63.40% |
| 每季至少100次测速 | 132/216＝61.11% |
| 延迟还需在两个后续季度都增加至少5ms | 238/416＝57.21% |
| 延迟还需都增加至少10ms | 187/365＝51.23% |
| 排除跨偏远类别的网格 | 150/244＝61.48% |

**为什么：** 不能只挑最有利的规则；也要避免基准延迟很低时，微小绝对变化被百分比放大。

**实际结论：** 各变体仍有大量下载规则没有涵盖的记录，但具体数值随定义变化。不能把任何一个比例当成普遍常数。按地区整段历史重采样1,000次，主比例的95%区间为55.21%–63.17%；这种区间仍不能消除自选择测速偏差。

## 第8步：验证、报告与实际用途

**做了什么：** 编写19项规则测试；另写不调用主分析函数的逐行复算程序，核对37,449条状态、所有主标签和29个季度文件的哈希。输出四张图的PNG/PDF版本、机器可读CSV和英文报告段落。

**为什么：** 学校要求不只是展示数字，还要交代方法、评价、限制和结果用途。测试用于验证代码规则，不能当成预测模型的测试集性能。

**建议用途：** 已标记的地区先由人员复核；数据少的地区进入“优先补测”清单，而不是直接进入“无需处理”或“需要维修”清单。与组员预测输出的整合目前只是建议，没有实现自动维修或部署系统。

**还要由小组完成：** 对照原proposal解释范围变化；审阅英文初稿和图；把本实验与其他部分合并成不超过10页正文的报告；补充实际AI使用记录与人工核查；完成GitHub账号授权和分支审阅。不能把这些未完成的事项写成已完成。
